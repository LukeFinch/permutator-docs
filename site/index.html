Your token system, multiplied out for you.

Permutator is a Figma plugin for design-system teams. It reads the naming vocabulary already in your variables, then generates, rewires and audits tokens from it: twenty tools for the work that usually means hours of clicking through the variables panel.

Toggle a keyword. This is the idea behind Keyword Groups, Semantics and Surface: define each vocabulary once and let the plugin work out every combination.

Names become structure

Variable names like color/blue/500 already encode hue and step. Keyword groups capture that once, and every generator in the plugin reuses it.

Bulk changes, previewed first

Rebinds, migrations and syncs show what will change before you apply. Large token sets get handled in one pass instead of layer by layer.

Audits that touch nothing

The scanning tools only read. Find unused, deprecated and orphaned dependencies before a library update, with nothing replaced, detached or deleted.

1 / 4

Generate

Keyword Groups

Split variable names into segments and sort them into groups by meaning: hues, ramp steps, roles, states. Saved groups power the keyword-based tools across the plugin.

Why it helps.One shared definition of your naming scheme, so every generator speaks the same language.

color/blue/500 → hue: blue · step: 500

Color

Generate colour scales with Adobe Leonardo and write them straight into a collection as primitive variables. Adjust individual shades before you commit.

Why it helps.Ramps are built against contrast targets, so accessible pairings come from the maths instead of eyeballing.

blue/100 · blue/200 · … · blue/900

Semantics

Create semantic aliases by mapping keywords from one group onto another. Point a role at a hue and every step follows.

Why it helps.A whole semantic layer from one mapping, with every alias pointing at the right primitive.

blue → brand · color/brand/500 = color/blue/500

Build the vocabulary, the colour primitives and the semantic layer that the rest of your system aliases.

2 / 4

Experimental

Surface

Combine keywords from several groups into surface tokens, then choose the background, foreground and border scale for each combination, with live colour previews.

Why it helps.Every role × prominence × state combination is covered, and none gets forgotten.

surface/brand/high/hover → bg · fg · border

Opacity

Create opacity variants of colour variables. Each one is named after its source, so the relationship stays readable in the panel.

Why it helps.Overlays, scrims and tints become tokens rather than hand-typed alpha values.

hue/100 → hue/100@50 · hue/100@20

Substrate New

Annotate components with an elevation offset from the surface beneath them, or a fixed level. Then pick the substrate a selection sits on and apply: every annotated layer inside gets its matching surface mode.

Why it helps.Cards in panels in sheets land on the right surface automatically, however deep they nest.

on surface-2 → card +1 = surface-3 · popover +2 = surface-5

Shadows

Generate elevation-aware shadow styles from your colour variables. Tune layers, levels, light angle, distance, intensity and the step between elevations, then copy the CSS.

Why it helps.Layered shadows with a consistent light source, in Figma and in code.

elevation/low … elevation/extreme · 90° light from above

Surfaces, transparency, elevation and depth. Newer tools that push past what Figma's variables panel does on its own.

3 / 4

Variables

Variables

Browse every variable in the file, filtered by collection, type or name, and see what each one aliases.

Why it helps.A searchable view of large token sets that the native panel makes slow to scan.

Collections

View your variable collections with their modes, and export any of them as JSON for backup or migration.

Why it helps.A snapshot to version, diff or hand to a build pipeline.

Primitives.json · 3 modes · 412 variables

Find & Replace

Search variables by name and rebind the selected layers to the renamed equivalents.

Why it helps.A naming change in the library no longer means re-picking variables layer by layer.

gray/700 → neutral/700

Variable Swap

Swap variables and styles by name, or generate component permutations: map component properties to keyword groups and create every variant combination.

Why it helps.A full variant matrix built for you, rather than duplicated and recoloured by hand.

variant[primary, secondary] × size[sm, md, lg] = 6 variants

Hot Swap New

Try alternative values for a group of variables in a sandbox collection. Switch its mode to preview a variant across real screens, then finalise to write the winner back.

Why it helps.Compare palettes in context without touching the live tokens until you've decided.

mode: current | option-a | option-b → finalise

Migrate

Rebind nodes from one collection's variables to the same-named variables in another.

Why it helps.Move a file onto a new library or a restructured collection in one pass.

Legacy/brand/500 → Core/brand/500

Sync from JSON

Bring a collection back in from a modified copy of the file. Permutator updates changed values, deletes removed variables and creates new ones, and tells you when there's nothing to apply.

Why it helps.Work on tokens in a branch file or a script, then merge the result back cleanly.

12 updated · 3 created · 1 deleted

Dealias

Rebind layers from an alias directly to the variable it points to.

Why it helps.Flatten a hierarchy, debug a chain of aliases, or convert semantic tokens to primitives before restructuring.

fill: danger → fill: red-500

Move, rename, swap and flatten the variables your layers are bound to, across a selection or the whole file.

4 / 4

Audit

Inspect Read-only

See which variables a selection uses, including every nested layer in deep mode. Or audit the whole document: usage counts per variable, unused variables, and a filter for the ones that are safe to remove.

Why it helps."Safe to remove" means no canvas usage and nothing aliasing it, so clean-ups don't break anything.

Orphan Scan New Read-only

Find layers and styles that still depend on deleted, deprecated or [OLD] variable collections, grouped by page and container.

Why it helps.The last stragglers after a migration, found before they ship.

[OLD] Brand 2023 → 18 layers on 4 pages

Deprecation Audit New Read-only

Find deprecated components and everywhere they are used. Define matching rules, skip pages or containers, and keep a saved report. Nothing is replaced, detached, unlocked, renamed or deleted.

Why it helps.A clear list to hand to the teams who own each screen.

Alias Matrix

Create alias variables where each colour keyword becomes a mode and each ramp keyword becomes a variable, aliasing prefix/<colour>/<ramp>. A preview grid flags any source variable that's missing.

Why it helps.One set of accent tokens that can be any hue, switched by mode.

accent/500 modes: blue · green · red

Deprecate & Replace

Scan a selected node for every variable and style it uses, including ones from team libraries, then choose replacements from compatible local ones. Ban an item to flag it as deprecated in every file you open.

Why it helps.Retire an old token and see it flagged wherever it turns up next.

Know what's used, what's stale and what depends on what, before you change a library that other files rely on.

Sequence

  1. UnderstandBrowse Variables, Inspect usage, define Keyword Groups.
  2. GenerateColor ramps, Opacity variants, Shadows.
  3. MapSemantics, Surface and Alias Matrix build the semantic layer.
  4. ApplyMigrate, Find & Replace and Variable Swap rebind your screens.
  5. MaintainOrphan Scan and Deprecation Audit keep it clean.

The tools work on their own, but they're designed to chain. This is a typical run through a design system, from a messy file to a maintained one.
